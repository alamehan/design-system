Component Reference Gallery

Plain HTML + CSS, token-pure. Open directly in a browser. This is the visual truth for all components — every catalog/components/<code>.md links back here by anchor, so section ids are a contract and never change.
Part 1 — Base components (Assets → Atoms → Molecules → Composites → Layout → Organisms) is the default grounding tier. Part 2 — Composed samples shows assembled screens; consult it only when the task needs that level of detail — composed-05 is the one to copy for any non-trivial table. Part 3 — Derived, pending design review

Built from each spec’s own JSON — tokens, typography and anatomy — and never checked against Figma. Layout decisions the spec does not state were made here. They are gate-clean (token-pure, on the type ramp, no duplicate ids, no overflow at either viewport), which makes them safe to read — it does not make them approved.
How to use one: treat it as a reference, not as visual truth. Ground on the spec JSON first; copy a derived rendering only where it agrees with that spec, and where it is silent prefer a reviewed component from Part 1 over anything invented here. If your requirement and the rendering disagree, the spec wins and the difference goes to the design system author. Never present work built on one as design-approved.
Approving a rendering is one line: drop data-derived="true" from its section and it leaves this group, the banner disappears and the catalog drops the caveat at the next build.
